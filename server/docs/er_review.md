# ER model review (plan section 5)

Review of IMPLEMENTATION_PLAN.md sections 5.1 to 5.4 before the baseline migration
(`0001_baseline`). Items marked **decided** are applied in the baseline; **open** items need a
plan update or a later migration.

## Issues and ambiguities

1. **`user` is a reserved word** in PostgreSQL. Unquoted, `SELECT user` silently returns the
   current role instead of failing. **Decided:** keep the plan's name, always quoted (`"user"`).
   SQLAlchemy and Alembic quote it automatically; any hand-written SQL must quote it too.
   Renaming to `app_user` later is a cheap migration if the quoting becomes a nuisance.
2. **`climb_segment` partitioning vs `UNIQUE(device_id, id)`** (open, Week 2). On a partitioned
   table every unique constraint and PK must include the partition key, so the constraint has
   to be `UNIQUE(device_id, id, started_at)` and the PK `(id, started_at)`. Idempotency then
   holds only if the client resends the same `started_at` for a given `id` (it should, the
   segment is immutable on the client). Also, `fraud_flag.segment_id` cannot reference
   `climb_segment(id)` alone: it needs `segment_started_at` as well for a composite FK.
3. **`climb_segment` redundancy** (open). `user_id` is derivable from `device.user_id`, and
   `building_id` from `checkin.building_id`. Keep them for the hot-path indexes in 5.3, but
   guard consistency with composite FKs (`(device_id, user_id) -> device(id, user_id)`,
   `(checkin_id, building_id) -> checkin(id, building_id)`), which need matching unique keys.
   Nullability of `checkin_id` is unspecified (can a segment exist without a check-in?).
4. **Integer PKs**: `team.id`, `season.id`, `building.id` are `int`. **Decided:**
   `integer GENERATED BY DEFAULT AS IDENTITY` (not `serial`), so seeds can pin ids. UUID PKs
   use `DEFAULT gen_random_uuid()` (built in since PG 13, no `pgcrypto` needed).
5. **ON DELETE rules** (5.2 says user-owned FKs cascade). **Decided:** `device.user_id`,
   `team_membership.user_id`, `refresh_token.user_id` are `ON DELETE CASCADE`; references to
   reference data (`team_membership.season_id`, `team_membership.team_id`) keep the default
   `NO ACTION`. Open: deleting a user cascades to their segments, but the derived
   `team_building_score` and `building_claim` are not user-owned, so they go stale until a
   recompute. Decide whether account deletion triggers a recompute or scores are kept as is.
6. **Season exclusion constraint**: `&&` on ranges is supported by the built-in GiST range
   opclass, so **`btree_gist` is not needed** (it would only be needed to add scalar columns,
   e.g. `team_id WITH =`). **Decided:** also `CHECK (NOT isempty(active_during))`. Open:
   whether unbounded ranges (no end date) are allowed; seasons have no name/number column.
7. **Missing columns** in 5.1 (only "key ones" listed). **Decided** in baseline:
   `created_at timestamptz NOT NULL DEFAULT now()` on `user`, `device`, `team_membership`,
   `refresh_token`; `refresh_token.expires_at timestamptz NOT NULL` (a refresh token without
   an expiry cannot be validated). Open: `team.name` (display name of the faculty),
   `checkin.created_at`, `climb_segment.ended_at` / `received_at`, `refresh_token.device_id`.
8. **NULL rules are unspecified** in 5.1. **Decided:** everything `NOT NULL` except
   `device.last_seen_at` and `refresh_token.revoked_at`.
9. **Enumerated text columns** (`checkin.method`, `climb_segment.status`) need
   `CHECK (... IN (...))` constraints; `team.color_hex` gets
   `CHECK (color_hex ~ '^#[0-9A-Fa-f]{6}$')` (**decided**).
10. **Geofence query vs index** (5.3). `ST_DWithin` with a 30 m tolerance on SRID 4326 works in
    degrees; casting to `geography` bypasses the geometry GiST index. Either use
    `ST_DWithin(footprint::geography, ...)` with a functional geography index, or buffer in a
    projected SRID. Also `Polygon` rejects multi-part buildings; `MultiPolygon` may be safer
    (open; baseline follows the plan: `geometry(Polygon, 4326)`).
11. **Missing FK indexes**: PostgreSQL does not index FK columns. **Decided:** indexes on
    `device.user_id`, `refresh_token.user_id` (cascade deletes) and `refresh_token.family_id`
    (revoke a whole family on reuse detection).
12. **`checkin.valid_during`**: no exclusion against overlapping check-ins of the same user;
    that would need `btree_gist` (`user_id WITH =, valid_during WITH &&`). Open.
13. **Extensions on downgrade**: `postgis` is shared with other extensions (the
    `postgis/postgis` image also installs `postgis_topology` and `postgis_tiger_geocoder`).
    **Decided:** the baseline creates `postgis` and `citext` with `IF NOT EXISTS` and the
    downgrade drops tables only, not extensions.
